Because these **P1** issues directly affect authorization, secret isolation, lease concurrency integrity, and Universal sign-up correctness — alongside missing external operator authorisation and unprovisioned staging/Cloudflare trust config — **controlled external validation is explicitly `BLOCKED / NO-GO`**.

## 5. Detailed Audit B — Managed Email Lease State Machine Verification

### Verified State Transitions & Safeguards
- **Atomic cross-application claim:** `ManagedMailVerificationProvider.tryReserveManagedMessage()` (`193–210`) updates conditionally (`consumed_at IS NULL AND content_encrypted IS NOT NULL AND (reserved_at IS NULL OR reservation_expires_at <= now())`); `V072:92–100` partial unique indexes (`WHERE status IN ('RESERVED', 'CONSUMED')`) block duplicate active leases on the same source message while allowing re-acquisition after `EXPIRED`/`RELEASED`.
- **Token rotation & constant-time check:** `MailboxVerificationController` generates 32-byte `SecureRandom` tokens (`512–516`), stores SHA-256 hashes, verifies via `MessageDigest.isEqual` (`527–532`), and rotates `reservation_token_sha256` on Path A crash recovery (`265–279`), blocking stale-token `/confirm` or `/release` replays with `409 Conflict` (`384–386`, `456–458`).
- **`release` vs `confirm`:** `/release` (`466–474`) transitions to `RELEASED` and clears reservation columns via `releaseManagedMessage` (`230–244`) while preserving `content_encrypted` (idempotent on retry at `460–462`). `/confirm` (`412–423`) transitions to `CONSUMED` and permanently erases `content_encrypted` via `markResolved` (`248–262`), idempotent for the active token (`388–393`) and rejecting expired leases with `409` (`397–407`).

### Verified Defects (`P1` / `P2` / `P3`)
1. **`P1-1`: Pre-signup `applicant_identities` write breaks Universal & Workday account creation:**
   - Calling `POST /api/v1/apply/applications/{id}/package` runs `UniversalBrowserPlanService.assembleWorkerPlanPayload` (`410`) or `WorkdayExecutionPlanService` (`190`) -> `RegistrationIdentityService.resolveApplicationContactEmail()` (`256–262`, `279–285`), which inserts a row into `applicant_identities` with `provider = 'ROBIN_MANAGED'` *before* any employer account exists. Calling `POST /universal-account` or `POST /workday-account` afterwards calls `registrationIdentities.resolve()` (`UniversalBrowserPlanService:260`, `WorkdayExecutionPlanService:412`), observes `existing == true` (`RegistrationIdentityService:118–134, 168`), and throws `409 IDENTITY_ALREADY_REGISTERED`.
   - Even without `POST /package`, `UniversalBrowserPlanService.authorizeAccountCreation()` (`260–261`) calls `registrationIdentities.resolve()`, inserting the row into `applicant_identities` up front. When the Playwright worker reaches the signup wall and calls `POST /api/v1/mailbox-verification/registration-identity` (`browser_worker.js:2871`), `RegistrationIdentityService.resolve()` finds that row, sets `alreadyRegistered = true`, and returns `existing: true`. `browser_worker.js:2872–2880` treats `identity.existing` as an existing employer account and either switches to login (failing on a non-existent account) or pauses with `UNIVERSAL_ACCOUNT_ALREADY_EXISTS`. (Tests missed this because `CloudflareTrustedAuthOtpIT:389` omitted both prior `POST /package` and worker `/registration-identity`, while `universal_account_otp_recovery.test.js:263` mocked `existing: false`.)
2. **`P1-2`: `ManagedMailRetentionJob.purge()` `READ COMMITTED` TOCTOU race:**
   - `ManagedMailRetentionJob.purge()` (`83–131`) has no `@Transactional` and runs statements 1–4 using non-locking `SELECT id ... LIMIT 1000` subqueries with **no predicate re-checks on the outer `UPDATE`/`DELETE`**. Under PostgreSQL `READ COMMITTED` (`EvalPlanQual`), a concurrent `/resolve` (`tryReserveManagedMessage` or `refreshManagedLease`) that extends `reservation_expires_at` / `reserved_until` before `purge()`'s outer `UPDATE` executes can still have its row overwritten to `EXPIRED` (line `88–94`) or its `content_encrypted` erased and reservation columns nullified (line `106–120`). Statement 1 (`90`) also omits `reserved_until = null`, and Statement 4 (`121–124`) lacks an active-lease guard (`reservation_expires_at is null or reservation_expires_at <= ?`). Additionally, `ManagedMailRetentionJob` never prunes terminal `mailbox_verifications` rows (`P2-5`).
3. **`P1-6`: `sessionId = null` bypass & missing `ApplicationBinding` on verification lease routes:**
   - When `r.sessionId() == null`, `/resolve` (`MailboxVerificationController.java:180–213`) skips closed-session (`HARD_STOP`/`FAILED`/`COMPLETED`), `expected_domain`, `sessionStart`, and `registered_email` checks (verified in `ManagedMailIT:517`), and `/confirm` (`379`) skips session parity (`if (r.sessionId() != null && sessionBound != null && ...)`), while `/release` ignores `sessionId` altogether (`444–478`).
   - Unlike `EmployerCredentialController.resolve()` (`113–119`), `MailboxVerificationController` injects no `EmployerCredentialService.ApplicationBinding` check (`running()` + `permittedDomains`), permitting any worker-token caller to lease/consume OTPs for applications with no active `RUNNING` run or arbitrary domains (assuming `ownerOfApplication` succeeds).
4. **Concurrent initial-acquisition race & clock mixing (`P2-3`):**
   - Path A's `FOR UPDATE` (`MailboxVerificationController.java:234`) locks zero rows when no active lease exists yet. Two concurrent workers for the same `(applicationId, sessionId)` both enter Path B (`302–347`): if they target the same message, the loser hits `tryReserveManagedMessage == false` or `DuplicateKeyException` and returns **`404` instead of recovering the winner's lease**; if multiple messages exist or `V072` lacks a partial unique active-lease index per `(application_id, coalesce(account_session_id, sentinel))`, two simultaneous `RESERVED` leases can exist (`Gmail` uses non-atomic `count(*)` at `307–314`).
